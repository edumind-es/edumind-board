# Auditoria tecnica - 2026-06-01

## Alcance

Revision pre-release de rutas, flujos incompletos, placeholders, contratos API/web, Hub embed, sala de aula y validacion de build.

## Hallazgos corregidos

- El panel de sala mostraba un enlace hardcodeado `/proyector/TOKEN`. Ahora usa el token real del primer enlace compartido activo o informa que hay que publicar/compartir antes de abrir proyector.
- Las respuestas historicas de sala llegaban al frontend como `student_label` y `created_at`, pero el componente esperaba `studentLabel` y `createdAt`. El backend ahora serializa consistentemente en camelCase.
- El boton `Limpiar` respuestas solo limpiaba el estado local y las respuestas reaparecian al reconectar. Se anadio `DELETE /api/sala/:code/responses` con autenticacion docente y broadcast `responses:cleared`.
- La sincronizacion de sala marcaba exito aunque el `PUT /api/sala/:code/board` devolviera error HTTP. Ahora valida `response.ok` y muestra error de sincronizacion.
- El bus SSE de sala dependia solo de memoria de proceso. Ahora cada evento se persiste en `classroom_events`, se emite por SSE con `id`, y cada proceso puede recuperar eventos nuevos mediante polling incremental sobre SQLite.
- La busqueda ARASAAC se hacia directamente desde el inspector. Ahora pasa por `/api/arasaac/search`, con cache persistente en `arasaac_search_cache`, TTL configurable y fallback stale si ARASAAC no responde.
- Pasos tenia `caniuse-lite` desactualizado. Se ejecuto `npx update-browserslist-db@latest`; el build posterior ya no muestra el aviso.
- Se anadio `npm run check:contracts` para validar contratos premium: elementos colaborativos, algoritmo con resto, embeds permitidos, rutas ARASAAC, tablas de resiliencia y uso del proxy ARASAAC en frontend.

## Riesgos abiertos

- Falta prueba con navegador real para sala completa: docente crea sala, alumno conecta, responde, docente limpia respuestas y proyector abre token real.
- La vista proyector depende de que exista al menos un enlace compartido activo; es correcto funcionalmente, pero conviene un CTA directo para publicar/compartir desde el panel de sala.
- La capa de eventos de sala ya es multiproceso en un mismo SQLite compartido. Para varios nodos o alta concurrencia sostenida, la decision recomendada es Redis Streams como bus productivo, manteniendo SQLite como modo local/contingencia. Propuesta tecnica: `docs/classroom-realtime-scale-architecture-2026-06-01.md`.
- ARASAAC ya tiene cache de busqueda; las imagenes siguen sirviendose desde ARASAAC. Una fase superior puede cachear thumbnails o servirlos desde storage propio.
